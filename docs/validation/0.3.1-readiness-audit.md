# Design Arc 0.3.1 readiness audit

Date: 2026-08-10

## Release purpose

Design Arc `0.3.1` makes activation truthfulness explicit. Direct invocation remains frictionless; if Codex selects the skill indirectly, it asks before Design Arc begins work. The patch also makes the upgrade harness version-aware so future patch releases can prove preservation without rewriting release-specific logic.

## Requirement audit

| Requirement | Evidence |
| --- | --- |
| Direct invocation starts without a redundant question | Deterministic activation contract and mutation `consent direct invocation`. |
| An indirectly selected skill requires permission | Deterministic activation contract and mutation `consent required outside direct invocation`. |
| No setup, inspection, research, or record creation before approval | Mutation `consent pre-approval isolation` and documentation contract. |
| Declining leaves the ordinary request outside Design Arc control | Mutation `consent decline boundary`. |
| Package is discoverable as exactly one `design-arc` plugin and skill | Identity, fresh-install, migration, and fresh prompt-load checks. |
| Existing project state survives upgrade | Isolated public `0.3.0` to `0.3.1` proof preserves two projects byte-for-byte. |
| Unprefixed requests are not falsely credited to Design Arc | Fresh isolated task evidence plus mutation `unprefixed selection integrity`; starter prompts now invoke `$design-arc`. |
| Existing evidence, approval, graph, repair, safety, and release boundaries remain intact | Complete workflow checker and all 179 mutation rejections. |

## Release boundaries

Repository publication, installation into the laptop's Codex profile, and mutation of project state are separate operations. Publishing this candidate does not by itself upgrade the installed plugin. Upgrading the installed plugin does not authorize setup, review continuation, source implementation, staging, deployment, or release in any product project.

## Known limits

The deterministic contract suite validates packaged instructions; it does not prove that every future model follows them. The isolated CLI fixture proves package identity and byte preservation for its two temporary projects; it does not inspect every real project on the laptop. Stitch remains a separately authorized visualization tool, and its renders still require inspection under the bounded correction contract.

## Whole-candidate review

An independent uncommitted-diff review found two release blockers after the first full green run: the copyable prompt examples still promised automatic unprefixed activation, and the generalized upgrade harness could report an environment-supplied target version that disagreed with the manifest. The examples now use explicit `$design-arc` starters and state the real selection boundary. The harness now derives its authoritative target from the manifest and fails immediately on an override mismatch. Focused regressions and the complete validator passed after both repairs.
