Design Arc is one shared workflow. The active host owns only the runtime-specific installation, invocation, saved state, return path, visualization capability, and upgrade behavior.

The [Codex runtime](codex.md), [Claude Code runtime](claude-code.md), and [Google Antigravity runtime](antigravity.md) pages are the authoritative guides for those host-specific details. They describe their own installation and return paths without turning any host into the default for the shared product journey.

## What remains shared

Objective Confirmation, both evidence modes, the Direction Gate, the Visual Proposal Gate, complete-state validation, optional Stitch, and the three-round correction limit are shared workflow contracts. The active host follows the same Design Arc methodology: establish the outcome before inspection or research; distinguish first-party guidance, inspected precedent, and product judgment; recommend a direction with alternatives and trade-offs; and inspect the complete proposal before the visual verdict.

Guidelines only performs no benchmark lookup or benchmark-evidence claim. Guidelines + Benchmarks requires separately authorized, relevant inspected journeys and current first-party guidance for every affected platform. First-party guidance remains authoritative for its platform: Apple guidance governs Apple targets, while current Android or web guidance overrides conflicting Apple-inspired judgment on those targets.

The active host produces a reviewable proposal, and Stitch remains an optional, separately authorized visualization workspace. Neither a board nor a Stitch prototype proves accessibility, safe-area behavior, native or browser behavior, physical-device quality, or implementation readiness. The active host can make at most three proposal-wide correction rounds, reinspecting the complete result after every replacement.

## What remains separate

Codex, Claude Code, and Google Antigravity never merge, migrate, resume, or continue an active review across runtimes. Each runtime keeps its own saved state, review records, return path, and upgrade lifecycle. A host-specific project home, reminder, command, or visual capability is not a shared Design Arc requirement and does not create cross-runtime synchronization.

Use the [Codex runtime](codex.md) page for Codex-only details, including project homes. Use the [Claude Code runtime](claude-code.md) page for Claude Code-only details, including its optional project reminder. Use the [Google Antigravity runtime](antigravity.md) page for Antigravity-only installation, `/design-arc`, and `.gemini/` state details. Use [Upgrades and migration](upgrades-and-migration.md) for the current upgrade path and preservation rules.

## Implementation and release boundary

No runtime detail or approval authorizes source implementation, staging, deployment, or release. A validated visual journey is a design proposal only. Product-source changes, provider access, destructive actions, staging, deployment, and release each require their own scope, authorized owner, and current evidence.
